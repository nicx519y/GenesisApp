# MiniPhone UI 更新 — 2026-10-18

基于团队 `origin/miniphone` 的 `7aa4b434`，提交至独立分支 `feature/miniphone-review-20261018`。

## 变更清单

- **Posts**：作者头像固定宽度、左对齐；包含已加载的全部世界角色，空 Feed 也保留角色入口。
- **Create Post**：统一页面 Header；作者、正文、可选图片依次排列；底部固定全宽 Post 按钮。正文限制 500 个用户可见字符并显示计数，支持输入法组合输入。旧版已提交但结果未确认的请求保留原正文重试。
- **Home 音乐卡片**：压缩进度条周围及卡片上下留白，正常字号下总高度减少约 22px，保留竖图与播放按钮大小。
- **Music**：标题字号由 24 调至 20；点赞与标题同行，作者和来源放在下方。
- **Photos**：同一图片 URL 只展示一次，网格与大图翻页使用同一列表；内容不足一屏或接近列表底部时自动续载，保留请求中及错误状态保护。
- **Photos 内容过滤**：排除系统默认地图／地点图、空资源和当前 Worldo 封面；识别封面的已注册原图／缩略图变体，原始接口记录不删除。
- **时间**：入口 icon、Home 和设置预览共用真实世界时间；仅入口 icon 在时间缺失或无效时显示 `18:05`，Home 和设置预览留空。

## 验证与边界

- 当前 MiniPhone 目录静态分析和 `git diff --check` 已执行，结果见任务 checkpoint。
- 各轮 UI 已通过现有 Android Debug 应用热重启预览；本次未重新打包，未运行自动化测试／全量回归。
- 真机只读数据检查确认：一个世界首屏 10 个资产条目实际对应 5 张图片；自动续载后取得全部 24 条记录、15 个不同 URL，包括 5 个角色头像。默认地点图和封面过滤在此基础上实施。
- 另一个世界的相册请求成功但返回 0 条且无后续页，同时角色头像实际存在。当前后端不补登记历史世界资源，这类空相册仍需后端补登记；本分支没有修改后端。
- 去重基于资源 URL，不做图片内容指纹识别。接口没有资源来源类型；封面过滤使用当前 World 详情中的封面资源。
- 本地 Flutter SDK 自动改动的 `analysis_options.yaml`、`pubspec.lock` 不包含在本次提交中。

完整接口和交互约束见 [MiniPhone 集成说明](mini-phone-client-integration.md)。
