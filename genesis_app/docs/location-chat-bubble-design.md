# Location Chat 基础气泡设计规范

本规范以当前正式 Location Chat 默认样式为准。所有尺寸为 Flutter 逻辑像素，百分比为不透明度。颜色指填充色本身，透明填充在不同背景上的最终观感会变化。

## 基础类型

| 类型 | 内容颜色 | 底色 | 圆角 | 内边距 | 背景模糊 |
| --- | --- | --- | --- | --- | --- |
| AI 角色 | 普通正文 `#F4F3F6`；`*…*` 斜体 `#888888` | `#3A3942`，60% | 左上 2，其余 14 | 左右 13，上下 11 | 14 |
| 自己发送 | 普通正文 `#F4F3F6`；`*…*` 斜体 `#888888` | `#C41F2E`，60% | 右上 2，其余 14 | 左右 13，上下 11 | 14 |
| Narrator 旁白 | 白色，73%；整段使用平台适配的斜体 | `#151517`，约 50%（alpha 128/255） | 四角 8 | 左右 12，上下 6 | 0 |
| 发送后等待回复 | 圆点 `#F4F3F6` | `#3A3942`，60% | 四角 14，无特殊角 | 左右 13，上下 11 | 0 |

AI 和自己发送的正文为 14、w400、行高 1.4。旁白为 14、w400、行高 1.3，带段落图标，采用整行系统消息布局。旁白中的 Markdown 斜体保持旁白正文颜色。

Edit 轮次编辑页为明确例外：页面使用 `args.style.copyWith(bubbleBackdropBlurSigma: 0)`，所有气泡关闭背景模糊，保留原底色、圆角和内边距。共用底框必须尊重调用方传入的 0，不能重新套用聊天默认模糊值。

等待回复底框左边缘与 AI 气泡左边缘对齐：列表左边距 10 + 头像宽 40 + 头像气泡间距 10 = 60。三个圆点每个占位 10×10，间隔 3，圆点基础直径 7，缩放 0.65～1.20，周期 1050ms、相位依次错开三分之一。底框默认 62×32，无头像和文字，背景模糊保持当前的 0，不因共享底框而自动启用。

Send（包括灵感回复）/ Go On 统一将 loading 上方紧邻气泡的实际下沿定位到 position，默认位于消息区域顶部往下 15%。由 `ChatBubbleGeometry` 在气泡装饰表面直接测量边界，包含气泡内边距，不包含头像、昵称、日期、外部行间距和操作栏；不得用整行高度减间距、loading 顶部或固定像素偏移代替。定位使用现有 220ms 动画。短历史不足以滚动时保持顶部边界，不添加顶部假占位。一次本地操作仅定位一次，ACK、最终消息 ID 替换及 loading 消失不重新定位。回复增长逐步填满预留空间，等待结束后也不自动追随底部。手动滚动可打断定位；用户主动发送或请求新回复时先布局目标行，不先跳到旧留白底部。预留高度不包含 Header 和输入区，等待定位不触发上翻历史加载。

点击输入区 Send 后，输入框主动失去焦点并收起键盘。新消息提示以真实消息底边是否超出消息视口为准，等待占位、操作区和消息底部间距不计入；同一条流式消息起初完整可见时不提示，后续增长超出视口后再提示。

Regenerate 新生成的当前候选卡同样参与提示，数量按内容底边超出视口的气泡逐条计算；同一气泡的多个流式片段只计一次，完整可见的气泡不计入。滚动露出气泡后数量相应减少，生成结束保留未查看提示；点击提示跳到底部并清除计数，浏览或恢复已有卡片不新增计数。

预留留白是可消耗的临时空间。手动向下拉动消息时（包含松手后的惯性），留白随视口下沿收缩；反向上拉不能重新撑高已消耗的留白。真实消息和操作区的自然高度始终保留，到达临时留白的底部也不会恢复自动跟随；新一轮 Send / Go On 等待仍可重新预留空间。

存在可见等待留白时，点击输入框打开键盘不再直接跳到留白底部。以聚焦前的滚动偏移 `s₀` 为基准，每帧按实际视口高度 `h(t)` 设置最小内容高度 `M(t) = s₀ + h(t)`，实际内容高度仍不得小于自然高度 `C(t)`。由原滚动协调器完成贴底修正：`s(t) = max(s₀, C(t) - h(t))`。因此键盘与聚焦快捷栏先消耗留白，留白充足时消息不移动；耗尽后只移动不足的距离。自然内容末端由实际布局标记测量，包含真实操作区与底部 padding，不写死气泡、间距或键盘高度。收起键盘恢复可用留白；手动滚动、新操作、失败重置或离开页面使旧聚焦基准失效。没有可见等待留白或关闭等待定位时，保持原聚焦贴底行为。

Regenerate 使用同一定位公式，锚点是点击时展示的旧 card 上方紧邻气泡的实际下沿（不属于 card 的那一条），不是 card 内最后一个气泡或 card 容器下沿。以旧展示列表锁定该气泡，快速返回的新 card 不得改变锚点；card 上方没有气泡时跳过定位。先保存旧 card 的展示快照，完成定位后固定滚动位置，再启动向上收起；旧 card 及上方行的间距不能因新的空卡状态而切换。收起减少的高度由尾部留白承接，最后一帧和新 card 接替时不再 jump。请求立即发送，提前到达的数据正常接收，但新 card 在定位和收起完成后才显示。旧卡的揭露时钟在快照期间暂停，收起出 lazy cache 不销毁其过渡状态；临时留白仍可由手动下拉消耗。

### 定位算法

统一使用消息列表的内容坐标（滚动起点为 0）：`s` 为滚动偏移，`b` 为气泡下沿全局坐标，`v` 为视口顶部全局坐标，`h` 为实际可见视口高度。定位比例使用键盘无关的参考高度 `H = h + K + E`：`K` 是本帧实际布局减少的高度（页面已应用的键盘占位加 Scaffold 实际压缩量），`E` 是输入框聚焦快捷栏实际增加的行高。外层面板、Scaffold body、输入框及相邻按钮均读取同帧布局；不使用原始系统键盘高度、固定快捷栏高度或旧帧缓存。`r` 为留白比例，`C` 为包含实际行间距和操作区、但不包含临时尾部的自然内容高度。Send（包括灵感回复）、Go On、Regenerate 均使用同一参考，打开和关闭键盘时的定位点一致；可见视口短于定位点时才限制到视口下沿。

```text
A = s + b - v                   // 气泡下沿的内容坐标
P = min(h, H × (1 - r))         // 共用参考位置；键盘不是额外的消息留白
S = max(0, A - P)               // 目标滚动偏移
M_prepare(t) = max(s(t), S) + h(t) // 定位期间每帧保证的最小内容高度，S 固定
M_hold = S + h                  // 定位完成时使用当前实际视口高度
T = max(0, M_hold - C)           // 临时尾部留白
```

可滚动时满足 `A - S = P`。气泡高度、昵称高度、行间距、按钮高度均不作为公式参数；它们只通过实际布局坐标和自然内容高度参与计算。先建立可滚动范围，再执行一次定位。定位动画中键盘收起导致视口变高时，每帧尾部必须保证 `max(当前滚动偏移, 固定目标偏移) + 当前视口高度`，不能只保住当前偏移，否则滚动边界会截停尚未到达目标的动画。定位完成时按最新视口高度进入保持，之后键盘收起也保住当前偏移；这些布局修正均不重新测量锚点或发起第二次定位。普通列表和二次滚动列表复用同一公式，由现有布局事务处理尺寸修正。

三条路径统一读取 `LocationChatBubbleLayoutSettings.replyWaitingPositioningEnabled` 和 `replyViewportReserveFraction`。等待定位默认开启，预留比例默认 `0.85`，即锚点位于消息视口顶部往下 15%。Developer Page 的 `switch → Reply positioning` 提供 `Hold reply position while waiting` 开关；关闭时不创建临时尾部、不进入等待锚定，Send / Go On / Regenerate 沿用贴底跟随。`Space below reply anchor` 可按 5% 步长调整为 25%–90%；开关关闭时滑杆禁用但保留数值，重新开启后继续使用。两项配置均保存到本地。

等待定位完成后，若消息队列裁剪了原锚点上方的历史，不能只锁住旧滚动数值。列表更新前记录原锚点行的实测内容坐标 `a₀` 和滚动偏移 `s₀`，布局完成后计算 `Δ = a₁ - a₀`，同帧由协调器修正到 `max(0, s₀ + Δ)`，并将保留的最小内容高度同步平移 `Δ`。旧留白先保留到修正生效，再释放多余高度，防止边界提前夹紧。只对原锚点上方的移除或替换建立一次性修正；下方回复增长、loading 消失和 card 收起不触发追随。锚点从候选卡转为正式历史时按业务消息身份衔接；手势、新操作、失败、关闭定位或离开地点使旧修正失效。裁剪与惰性测量修正共用这一入口，不叠加第二次 jump；保持回复时始终使用原回复锚点，不改为追随正在增长的新气泡。

普通消息行下方留白 14。最新回复到操作区使用独立的回复操作布局；不要用气泡内边距补偿操作区间距。所有几何描述以组件边缘/文字行框为准，实际字形和动态图案内部可能有空白。

等待定位开启且处于贴底跟随时，流式消息完成后如果最终正文或操作区前的行间距缩短，缩短的高度暂留在列表尾部，保持可见消息位置，避免跟随更小的滚动边界而下沉。后续新内容增长消耗尾部留白并继续正常跟随；不改变手动阅读历史或等待预留区域时的滚动状态。关闭等待定位后不保留这段临时高度，由原贴底机制直接跟随真实内容高度。

其他玩家/NPC 的左侧普通消息复用 `ChatMessageBubble`，当前保留左上角 0、其余 14 的既有分支；只有 AI 角色使用左上角 2。不得仅因消息位于左侧就判定为 AI。Opening 等调用方的明确样式覆盖继续生效。

普通消息的 self / other 仅由业务 `type == user` 且 `user_id` 精确等于当前登录用户非空 UID 决定。`sender_id`、角色绑定关系和开场选中的角色不作为 self 的兜底依据。历史与回复卡片使用同一规则；本地待发送的本人消息直接使用 self。

## 流式正文动画

Location Chat 的普通正文、旁白、系统、Tick、事件、角色移动和入场消息共用流式动画。普通底框通过 `ChatBubbleSurface` 接入，独立底框在自身装饰内部使用 `ChatStreamingBody`；动态正文由 `ChatStreamingText` 标记。头像、时间和固定图标不参与文字遮罩；编辑输入、图片加载、等待圆点及历史首次展示保持原有行为。其他页面未提供 `ChatStreamingEffects` 时不启用。

文字保留柔和边缘沿阅读方向连续扫出的效果，边缘宽度引用公共 token。`streamingTextDurationMs` 保留原存储键、数值与范围，作为每字素的基准时长；实际时长 `d = streamingTextDurationMs / 20`，相对之前的 10 倍系数再提速 2 倍，不受 chunk 大小影响。设已收到 `N` 个字素，已揭露进度为 `q`，每帧有效动画时间为 `Δt`：`q_next = min(N, q + Δt / d)`；默认实际 6ms，即每秒最多约 166.7 个字素。组合 emoji 和组合重音字符不可拆分。末尾柔边使用同速的独立收尾区间，不提前显示新的字素。

同一地点的待揭露任务按消息展示顺序串行揭露，不按 chunk 到达或懒布局挂载顺序并行播放。当前气泡在流结束、文字柔边及高度动画收尾后交棒；chunk 间隙保留播放权。排队气泡不推进动画时钟，轮到它时从原进度开始，不补播等待时间。卸载、切换卡片或 TickerMode 冻结的旧快照退出当前播放队列；恢复挂载时保留原揭露记录。未开始揭露的整条消息不占高度、不绘制、不响应点击或辅助功能，底框、头像、昵称、日期与行间距均在正文开始显示时一起出现；排队任务先登记完成屏障但不挂载正文；轮到当前任务才布局，即使位于屏幕外也仅固定这一条任务。图片和 AI 内容声明不进入文字任务队列。历史消息不加入队列，关闭遮罩仍立即全显。Send 后旧 card 转为普通历史时按业务消息 ID 识别已展示消息，不因 localId 或 card ID 改变而重播；新操作终止旧揭露任务。

新增 chunk 只扩充待揭露内容，剩余动画时长随剩余字素数量增长，不能加速追赶。空闲、后台、TickerMode 暂停或卸载期间不积累动画时间；重新挂载、临时 ID 替换及流结束保留进度。同一帧收到完整新回复也需要揭露，历史首次展示不重播。复合气泡按正文顺序揭示；后续行在揭示前不占展示高度。气泡从当前高度以 `easeOutCubic` 追踪已揭示内容的高度，新增行和减少行均平滑变化，文字不缩放。富文本行框和内嵌文字沿用实际 `RenderParagraph` 排版，保留 Markdown、提及、斜体、组合字符和双向文字。流式 Markdown 收到单个起始 `*` 后，后续正文立即按斜体乐观排版，闭合 `*` 到达时不重新改变这段文字的字体；如果消息结束时仍未闭合，则恢复未闭合标记及其后正文的普通文本展示。

Developer Page 的 `switch → Location Chat → Streaming animations` 提供四项本地持久化配置：

| 配置 | 默认 | 范围 |
| --- | --- | --- |
| Bubble height animation | 开启 | 开／关 |
| Height animation duration | 180ms | 40–1000ms，步长 20ms |
| Text reveal mask | 开启 | 开／关 |
| Text reveal duration per grapheme | 实际 6ms / 字素 | 实际 2–50ms，步长 1ms；存储仍为 40–1000ms，步长 20ms |

关闭某项立即结束对应动画；关闭遮罩显示全部已收到正文。对应滑块置灰但保留时长，重新开启只作用于后续变化。修改时长立即用于后续目标，不重启动画，松手保存；无配置或无效配置使用默认值或归一化边界。

动画不延后流结束或 Tick 的业务状态；Regenerate、Go On、Edit、Inspiration 四个按钮与 Send 共用完成条件：需同时满足「后端结束」「当前展示的全部气泡文字、柔边及高度动画完成」「card 过渡结束」才解锁。Send 从提交开始锁定，即使用户已输入下一条草稿，仍需等待同一完成条件；实际发送入口也检查此条件，不能绕过按钮触发。保留原来的非空输入、连接、Tick、权限和次数限制。结束帧先到时保留等待中的按钮快照，不提前恢复点击；同帧完整回复也先完成布局登记，不能出现一帧可点击窗口。后台暂停不算渲染完成，旧 card 的冻结快照不阻塞新 card；错误、Tick 和切换地点会清理旧等待状态。

逐帧高度变化通知列表更新真实内容可见性；保留等待留白、手动阅读和流结束收缩补偿。普通列表和二次滚动列表统一使用有限缓存的惰性视口，不再临时切到完整 Column 或扩大到全部已加载消息。消息与候选卡片的动画记录隔离，地点销毁时释放，历史恢复不重播。

退出地点页后重新进入，先按每条消息的接收状态判定：已收到结束、状态为 `sent` 的正文直接完整显示，丢弃其旧的未完成揭露任务；仍为 `streaming` 的正文继续走串行渐进式揭露，不能一律全显。此规则也覆盖页面保留但隐藏期间收到结束、以及异步恢复的已完成消息。恢复基线按消息及 card 身份隔离，不改写业务状态，按钮仍受后端完成条件约束。同一页面内的新消息结束帧不跳过剩余揭露；普通惰性卸载再挂载继续保留进度。

### 增量几何与消息内存窗口

- 每个消息条目保存自身布局高度；没有挂载的条目使用稳定的轻量占位，不创建正文、头像或 Markdown 排版。只布局视口缓存范围、原定位锚点、正在揭露的任务与当前 card/操作区。新 chunk 不改变历史条目的几何版本。
- 几何版本按宽度、文字缩放、文字方向、真实尺寸样式及消息内容比较，不能按样式对象引用比较。头像、内边距、行间距、字体或操作区布局变化会使对应记录失效；仅键盘改变视口高度不会清空历史几何。跨挂载的几何 LRU 目标为 512 条，保护当前画面和活动锚点；当前条目自身另保存稳定高度，LRU 淘汰不令其占位每帧重新估算。
- 未测量高度只用于屏外占位；等待定位仍直接读取已布局气泡表面，绝不使用估计气泡高度定位。绝对内容坐标随本帧条目布局更新，不作为永久缓存。上方估计变为实测或队列裁剪时，由同一个协调器在绘制前补偿锚点坐标差。
- 一次性滚动补偿由列表起点的消息 sliver 组在子项布局后发出，不能放在屏外尾部的零尺寸 sliver 上：尾部约束可能在视口重试时不变，导致缓存的补偿重复执行。组内未显示的尾部条目仍保持真实内容坐标，供屏外 Send 锚点测量使用；不额外挂载历史正文。
- 内存消息窗口目标 200 条、高水位 240 条。超过高水位才批量回收：保护当前视口及上下各一屏、原定位锚点、当前候选卡、发送中和流式消息，围绕当前阅读位置补足预算。最近 40 条包含在同一个预算中，不另加 40 条。保护集合超过预算时允许临时超限，保护解除后重新评估。
- 内存窗口与 SQLite 最新 200 条缓存独立。上翻仍按 20 条分页先读本地再请求远端，刚获取的页在合并时受到保护；同步释放 worldMessages 中同一地点已回收消息的重复引用。
- 围绕历史阅读位置保留的窗口与最新窗口之间可能有缺口。主动内存回收缺口不作为协议丢包自动修复，也不删除数据库或修改后端游标；缺口前显示 Load earlier messages，按需加载下一页。失败保留入口可重试，不把错误写入消息气泡。真正的后端缺口继续使用原修复流程。
- 验证区分组件测试与真机：200/2000 条条目的布局计数验证连续更新不重新布局中间历史；等待、键盘、收起、末帧和裁剪使用逐帧坐标断言。测试通过不等同于设备帧耗时或真实协议复现。

## 共用控件和 token

- `lib/components/chat/shared/chat_scene_plate_tokens.dart` 是基础气泡专用 token 的唯一入口：正文/斜体颜色、AI/自己/旁白底色、圆角、内边距、文字样式和等待圆点参数。
- `kLocationChatStyle` 负责把 token 组装为 `ChatUiStyleConfig`；页面应传递配置，不能复制颜色和尺寸。
- `ChatBubbleSurface` 统一底色、圆角、内边距、描边和可选模糊。由调用方负责对齐、最大宽度、头像和消息行间距。默认不启用模糊，启用时复用 `ChatStableBackdropSurface`。
- `ChatMessageBubble` 负责 AI、自己和其他玩家的正文、编辑态、身份圆角与手势，使用 `ChatBubbleSurface`。
- `ChatNarratorMessageBubble` 负责旁白语义和颜色，通过 `ChatSystemMessage` 使用同一个 `ChatBubbleSurface`。
- `ChatReplyWaitingBubble` 是可复用等待回复控件，使用同一个 `ChatBubbleSurface`，读取传入配置中的 AI 底色和正文色。页面只决定何时显示和移除，不重复实现圆点与底框。

增加或修改以上类型时，同时维护本表、token 和共用控件；特例在调用方明确说明，不改全局配置来补偿单个页面。Inspiration、额度提示、Tick 和入场提示属于独立模块，不能直接套用旁白或 AI 的整套样式。
