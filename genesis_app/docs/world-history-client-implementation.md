# World History 客户端实现

接口依据 [OpenAPI v1.1.0](client_world_history.yaml) 与[客户端对接文档](world-history-client-guide.md)。本次按用户提供的新契约接入，不代表已确认服务部署状态；客户端和受控测试不能证明线上权限、游标快照稳定性、完整历史或真机性能。

## 数据与展示边界

- `GenesisApi.getWorldHistory` → `ChatroomHttpApi.getWorldHistory`，复用 Chatroom 根地址 HTTP 客户端、登录 Header、Gateway 拦截器和取消 token。路径为 `/aitown-chat/api/v1/world/history`，不是主 API 的 `/api/v1/world`。默认 20 条，首次省略 cursor，其后原样传递，不传 user_id。
- `network/models/world_history.dart` 独立保存字符串消息 ID、服务端顺序、World 级游标。拒绝错误 World、非严格分页字段、未推进／循环游标；非零 err_no 保留原始错误。无旧消息接口回退。
- `WorldHistoryController` 保留当前阅读链的首页快照，并另存最近成功读取的最新首页。阅读分页内部同参数请求合并、不同操作串行；最新页同步使用独立的请求、取消代次和错误状态，各最多一个请求在途。回载接受编辑、删除、补写及首尾消息变化；下一页游标和 has_more 不变时仅替换当前页，改变时原子替换当前页并作废后续旧页、摘要及旧链排队操作。继续校验 World、响应格式、游标推进与循环，不自动连续请求重建历史。
- 接口每页消息按从旧到新返回，游标仍读取更早页。原始页缓存保留服务端正序；`WorldHistoryController` 在常驻索引和段落参与摘要入口将每页转换为内部 `newestFirst` 顺序，`WorldHistoryProjection` 再生成按地点折叠单位聚合的展示顺序。普通消息及其 location_refs 展开顺序保持不变；同一 Tick 在不同地点的展示副本归入各自折叠单位，每个单位内仍保持服务端消息顺序。跨页重叠消息仍以较新页为准。字符串 ID 与地点 ID 构成无歧义显示标识；不按 ID、时间、轮次排序。所有消息严格读取顶层必返整数 `tick` / `sub_tick`，保留 0 和原生 int64。History 的 Tick 气泡直接用它们填充现有共享标签：`Tick 7`、`Tick 7-3`、`Tick 0`；普通消息不因此生成 Tick 标题。旧 `tick_no` / `sub_tick_no` / `subtick_no` 不作为回退，不从世界状态或分页位置推算；聚合 Tick 和旧纯文本 Tick 共用该映射。
- 每条 Tick 的字符串正文懒解码一次。History 先按服务端顺序、版本过滤和地点关联划分折叠单位，再判断 Tick：只有所在单位含 `type=user` 消息才展示，用户发言可在 Tick 前或后，character/narrator 不算。Tick 的多个 location_refs 是并列归属，不能逐个视为地点切换；匹配的地点单位跨 Tick 连续，多个 Tick 的副本聚合在对应单位内，不因其他关联地点拆开。遇到不包含该地点的消息仍结束该单位，再次进入同一地点形成的新单位独立判断；隐藏纯 Tick 单位不合并两侧独立的同地点单位。参与判断与正文投影共用 `HistoryLocationSections` 分组。轻量参与索引按页保存 ID、类型、最低版本及地点单位，不保存正文；支持追加、替换、截断。跨页范围树聚合首尾仍连续的各地点单位及用户参与信息，单页更新不扫描全部历史；重复 ID 按较新页优先，归属转移只更新受影响页。正文回收保留摘要，旧页链作废同步移除摘要。
- 符合条件的地点继续展示共享旁白／时间／世界状态及该地点事件；History 不展示 `characters_moved`，普通 Chatroom/Events 不受影响。未知 visibility 不丢弃，缺失／null 可选数组按空数组处理，旧 Tick 纯文本仍使用原始正文但同样执行地点过滤。
- 普通消息空关联只显示一次，不生成地点段或跳转；无关联 Tick 无法匹配参与地点而不展示。未知地点显示 ID，元数据到达后更新名称、路径和背景；只有已知地点提供“在这里继续”。新增地点不影响分页状态，也不会补入旧 Tick 的关联。
- History 入场记录在接口中归一为 `type=user/message_type=text`，没有独立的入场标记。对单地点关联、发送者 ID 非空、全文符合 `sender_name entered 地点名` 或 `sender_name came to 地点名` 的记录，展示层使用共享入场文案解析，构建 `ChatUserEnterLocationPayloadVm`，由与 LocationChat 相同的 `ChatUserEnterLocationMessageBubble` 展示图标、底框和既有本地化文案。原始消息仍保留 user 类型参与地点折叠与 Tick 判断，不触发入场请求或等待定位；普通发言、旁白、图片、无关联和多地点关联不做此兼容。协议未提供独立标记，因此用户手动发送完全相同的入场格式无法区分，后续若提供正式标记应优先使用。

## 生命周期与窗口

- 常驻消息到页号的索引、去重消息数及 UTF-8 正文大小只在页内容变化时维护。阅读回调合并可见行和锚点保护；保护页集合未变时跳过回收检查。滚动不遍历已访问页目录，也不重新统计正文大小。

- History 底部居中显示双下箭头置底按钮，距底12：离开底部、最新页已回收、有待展示的新版本或有待核对通知时出现。与 Location Chatroom 新消息提示复用 `_LocationChatFloatingNotice`，底色0xCC1E1E24、圆角16、水平12/垂直8内边距，无额外边框或阴影，保留24px白色双下箭头；辅助提示复用 Material 本地化末页标签。点击立即采用已缓存的最新页并置底；仍待更新或同步失败时，同时合并一次最新页请求。没有新版本时恢复当前阅读链首页，不因置底重新拉取已有数据。采用新版本时原子建立新游标链，取消旧链请求，不拼接旧页；折叠选择不重置。

- 标签激活、当前路由可见、PagePresentationScope、TickerMode 和应用前台共同控制阅读分页与布局。暂停取消阅读分页和滚动防抖；恢复续接被取消的操作。首次用户请求可在 Sheet 关闭后完成。独立的最新页同步不受 History 标签／Sheet／Location 切换影响，但应用后台会取消；前台恢复标记待更新并校准。后台同步错误不弹 Toast、不丢缓存、不循环重试；主动查看最新失败时使用现有 Toast，分页错误沿用 Retry。
- 首次进入 History 使用静态骨架并加载首屏。`WorldPage` 持有 `WorldHistoryViewCache`，保留分页窗口、正文投影、折叠选择及共享列表的有界布局缓存和稳定消息阅读锚点。正在阅读旧消息时只更新最新页缓存，重开恢复原阅读位置；原先跟随最新则重开采用最新缓存。可见且停在底部时自动采用新版本；用户拖动期间不切换，滚动到原末尾并停止后可自动切换。退出 World 释放缓存，无磁盘缓存；失去访问资格、账号 sessionRevision（包括 Sheet 关闭期间）、服务实例／环境和 World 切换取消请求、解绑来源并清空旧状态，晚到响应不能提交。
- History 消息列表首次挂载时继续显示静态骨架，真实列表在相同约束下透明布局；首次置底前提前测量含“在这里继续”卡片的末行，重开时先恢复阅读锚点。定位完成且相邻布局帧的视口、滚动位置及行边界一致后，同步显示消息和地点卡片；不使用固定延时，不等待图片下载。准备期间不写入临时阅读锚点，显示切换保留原列表实例。该流程仅由 History 启用，普通聊天室保持既有展示时序。
- 当前阅读链的首页另保留一份不可变消息列表快照，按当前 World/账号/环境隔离；切标签、关闭 History、后台切换和窗口回收均保留。显式刷新或采用新版本后替换。首页约一页额外正文不计入滚动窗口预算；正常逐页回到首页也复用此缓存。同步另存至多一份最新页响应，不累积版本。每页保留请求游标、响应游标、has_more、首尾消息 ID；滚动窗口正文驻留预算为 1,000 条唯一消息或 8 MiB UTF-8 正文字节。按远离阅读位置的外侧整页回收，保持连续驻留区；可见区、共享滚动器锚点、展开定位页及相邻页暂时固定，超大单页不截断。
- 访问已回收的较新或较旧区段时使用原请求游标（首页直接恢复缓存，不发请求）。两端分别判断已回收区段与服务器终点；稳定显示 ID 交给共享聊天滚动器恢复锚点。回载失败保留窗口，原游标可重试。回载内容变化优先保留原可见消息的位置；可见范围全部失效时定位到更新页靠近原阅读方向的可见行，折叠段使用标题。更新页无可展示内容时保留现有加载入口。游标链改变后的程序定位不触发续页，下一次用户拖动或显式加载才恢复分页。
- 元数据索引只依赖角色身份／头像和地点路径／图片字段。时间与 Tick 计数不重建索引；相关列表替换但展示值不变时保持版本。展示复用 LRU 默认 300，当前可见项可固定；额外弱引用复用共享 viewport 仍持有的 VM。折叠索引只持有显示 ID，分组不创建完整 VM。共享列表可遍历轻量 VM 以定位，但 History 的 Tick 正文与地点事件展示对象延迟到实际访问气泡内容时解析；类型判断与布局版本比较不触发解析，普通聊天维持原有构造及赋值行为。页移出、刷新或上下文切换清理派生引用。
- 地点连续段落只在数据／元数据投影变化后更新。折叠仅更新该段隐藏状态，记住用户操作的轻量 ID，使回载后保持选择。整页被版本过滤且还有下一页时显示手动加载入口，不自动遍历全历史。
- 普通 LocationChat 保持 `fcc6100b` 之前的列表排列与定位行为：直接使用回复投影，不接入跨地点历史排序；共享列表不会仅因 `active` 恢复就额外清空等待空间／阅读锚点或调用 `enter()`，实际进入／离开仍由页面原有生命周期处理。拖动开始时提前捕获锚点由 History 显式启用；吸顶标题布局仅在传入 History 标题构建器时使用。History 的折叠定位与阅读缓存继续保留。

## World 新消息同步（2026-10-21）

- `WorldChatroomService.historyChanges` 只发送所属 World 的失效通知，不提供 History 正文；正式消息、普通流结束、`world_new_message`、`tick_done`、正式历史变更与重连触发。ACK、候选卡、手机事件和流式 chunk 不触发。
- 首次打开之前不预取；之后 World 缓存独立监听，隐藏期间只保存 HTTP 数据，不创建消息 VM 或布局。500ms 防抖，连续通知最长等待 2 秒；请求期间的新代次保留并触发后续同步。每次只读取 `cursor=null, limit=20`。
- 比较有序消息的全部展示及协议字段和 `has_more`，识别同 ID 编辑、删除、Tick 和关联变化。首次响应不变时 2 秒后校准一次，仍不变则保留待核对标记并停止计时请求；新通知、重新打开、前台恢复、重连或用户操作可再次核对。
- 新增超过一页时，采用新首页后沿新响应游标读取中间历史；不把新首页直接接在旧链前面。旧阅读链保持快照语义，不承诺全档案实时编辑／删除同步。
- 没有 History 提交版本或 WS 消息可查询确认字段；有限校准不能证明任意服务端延迟下的一致性，需真实后端验收通知与可读时序。

本次验证：History 全目录和接口、World 认证恢复／Location 容器／内容快照、聊天室服务、共享历史导航／折叠／滚动／等待回复共 330 项定向回归全部通过；12 个修改或新增 Dart 文件静态分析无问题，格式与差异检查通过。新增用例覆盖隐藏同步、首次请求关闭后完成、连续通知最大等待、单次延迟校准、在途新通知、失败无循环重试、旧链失效、同 ID 内容变化、空最新页、阅读锚点、底部跟随、拖动竞争、应用后台及会话隔离。未运行真机或真实后端验收。

## 2026-10-21 History 滚动与同步构建开销

- 最新页失效通知、请求开始／结束和待展示状态只更新置底提示。阅读列表仅在阅读链版本、首屏状态、分页加载或错误展示变化时重建；底部自动采用新内容、手动置底、空历史提示继续使用原流程。
- 共享列表提取不持有消息 VM 或已解析正文对象的布局快照（显示／布局 ID、条目键、类型标志、日期和内容版本值）。History 通过 `readOnlyArchive` 显式声明消息快照不可变，重复构建、折叠或装饰更新时复用快照；消息列表或布局 ID 映射变化后重新提取。普通聊天仍逐次更新以支持原地流式变化。滚动后的可见区、阅读位置和下方内容判定复用快照及本帧几何数据；布局高度回调复用已有布局 ID，不触发消息创建。
- History 每 24 个条目组成一组，离屏组只有总高度占位；只有视口缓存区或包含固定锚点的组挂载逐行 Sliver。稳定 ID 对应的高度由当前展示窗口持有，跨组、卸载及几何 LRU 淘汰仍保留，移出展示窗口后释放。嵌套组校正屏外锚点坐标，原阅读锚点和绘制前滚动补偿继续工作。普通聊天保留原逐行 Sliver 结构。布局仍需扫描当前窗口的轻量描述和高度；节点数和读取次数不等于耗时或帧率。
- 回归入口：`location_chat_visibility_cost_test.dart` 覆盖 200／600／1,200 条消息的稳定滚动，`world_history_live_widget_test.dart` 检查无内容变化的同步、阅读中缓存新内容时保留列表实例，以及空历史待更新提示。继续回归 History 全目录、共享滚动／等待回复／几何缓存／历史导航／折叠。
- 第二轮优化：几何缓存增量维护正值实测高度的总和及数量，估算均值无需遍历缓存；容量内不做淘汰遍历，超限仅暂存待淘汰键。真实消息位置查询限制到已挂载正文，包含候选卡和屏外固定锚点；普通滚动从挂载集合按消息顺序选择阅读锚点，离屏占位直接使用数值边界，保留完整的下方消息与保护集合。
- 第二轮回归另覆盖：缓存版本失效／高度替换／保护超限／淘汰／清空后的平均值，以及使用独立布局 ID 的远距离跳转、正文卸载重挂和阅读位置恢复。位置查询计数只表示受控组件中的工作量，不等同于真机帧耗时。
- 完整优化同时覆盖数据复用：校验分页／最新页响应后，将每条消息与当前持有的首页、最新页及对应常驻页比较；全部协议和展示字段（包括有序地点关联）相同时复用原对象，继续复用其 Tick 解码及仍在缓存的显示 VM。编辑过的消息替换，原阅读快照不变；不合并游标链，也不新增全档案正文缓存。
- 只读 History 不再重复登记流式任务、扫描接收标识或复制完整消息列表；地点标题和“在这里继续”装饰版本按显示 ID 查询，避免因装饰计算触发屏外 VM 创建。几何组自己保存估值，不用估值占用跨挂载 LRU；当前窗口高度随 `WorldHistoryViewCache.viewport` 跨 Sheet 保留，重开不因重新估值改变阅读偏移。离开当前窗口的条目及 World／账号缓存清空时释放相应记录。分页加载条收起后，即使复用了同一消息列表也提交一次界面更新，保证加载状态结束。
- 新增回归：1,200 条消息重复装饰更新及折叠时消息读取低于 200 次；200／600／1,200 条受控列表挂载逐行 Sliver 少于 160 个；2,000 条组件验证跨组重排、卸载、缓存清空、内容版本变化及远端固定锚点坐标。连续拖动、逐帧手势和重复翻页裁剪同时覆盖普通聊天与 `readOnlyArchive`。这些是受控工作量／行为断言，未测量真机 FPS 或帧耗时。

完整优化验证：History 全目录、接口解析、共享滚动／等待／回复切换／底部跟随／流恢复及新增性能回归 243 项通过；另两项候选回复与分页加载竞争回归通过，共 245 项。11 个实际修改或新增 Dart 文件静态分析无问题，格式与差异检查通过。扩大到全部聊天页面测试时发现 24 项原有失败及一个同步发送失败用例卡住；在独立临时目录中用修改前 HEAD 的代码复现了相同失败及卡住，未将大套件记录为全部通过。本次没有真机帧率或真实后端验收。
