# World History 客户端实现

接口依据 [OpenAPI v1.1.0](client_world_history.yaml) 与[客户端对接文档](world-history-client-guide.md)。本次按用户提供的新契约接入，不代表已确认服务部署状态；客户端和受控测试不能证明线上权限、游标快照稳定性、完整历史或真机性能。

## 数据与展示边界

- `GenesisApi.getWorldHistory` → `ChatroomHttpApi.getWorldHistory`，复用 Chatroom 根地址 HTTP 客户端、登录 Header、Gateway 拦截器和取消 token。路径为 `/aitown-chat/api/v1/world/history`，不是主 API 的 `/api/v1/world`。默认 20 条，首次省略 cursor，其后原样传递，不传 user_id。
- `network/models/world_history.dart` 独立保存字符串消息 ID、服务端顺序、World 级游标。拒绝错误 World、非严格分页字段、未推进／循环游标；非零 err_no 保留原始错误。无旧消息接口回退。
- `WorldHistoryController` 保留首次首页快照并管理可变的旧页链。同参数请求合并，不同操作串行；失败保留原内容与游标。回载接受编辑、删除、补写及首尾消息变化；下一页游标和 has_more 不变时仅替换当前页，改变时原子替换当前页并作废后续旧页、摘要及旧链排队操作。继续校验 World、响应格式、游标推进与循环，不自动连续请求重建历史。
- `WorldHistoryProjection` 仅逆转消息方向，保留每条 location_refs 顺序。字符串 ID 与地点 ID 构成无歧义显示标识；不按 ID、时间、轮次排序。所有消息严格读取顶层必返整数 `tick` / `sub_tick`，保留 0 和原生 int64。History 的 Tick 气泡直接用它们填充现有共享标签：`Tick 7`、`Tick 7-3`、`Tick 0`；普通消息不因此生成 Tick 标题。旧 `tick_no` / `sub_tick_no` / `subtick_no` 不作为回退，不从世界状态或分页位置推算；聚合 Tick 和旧纯文本 Tick 共用该映射。
- 每条 Tick 的字符串正文懒解码一次。History 先按服务端顺序、版本过滤和 location_refs 展开生成连续地点段落，再判断 Tick：只有所在可折叠段落含 `type=user` 消息才展示，用户发言可在 Tick 前或后，character/narrator 不算。再次进入同一地点形成的新段落独立判断；不跨地点段落借用用户发言。隐藏纯 Tick 段落也不合并两侧的同地点段落。轻量参与索引按页保存 ID、类型、最低版本及有序地点段落，不保存正文；支持追加、替换、截断。跨页范围树聚合首尾段落的用户参与信息，单页更新不扫描全部历史；重复 ID 按较新页优先，归属转移只更新受影响页。正文回收保留摘要，旧页链作废同步移除摘要。
- 符合条件的地点继续展示共享旁白／时间／世界状态及该地点事件；History 不展示 `characters_moved`，普通 Chatroom/Events 不受影响。未知 visibility 不丢弃，缺失／null 可选数组按空数组处理，旧 Tick 纯文本仍使用原始正文但同样执行地点过滤。
- 普通消息空关联只显示一次，不生成地点段或跳转；无关联 Tick 无法匹配参与地点而不展示。未知地点显示 ID，元数据到达后更新名称、路径和背景；只有已知地点提供“在这里继续”。新增地点不影响分页状态，也不会补入旧 Tick 的关联。

## 生命周期与窗口

- 常驻消息到页号的索引、去重消息数及 UTF-8 正文大小只在页内容变化时维护。阅读回调合并可见行和锚点保护；保护页集合未变时跳过回收检查。滚动不遍历已访问页目录，也不重新统计正文大小。

- History 底部居中显示双下箭头置底按钮，距底12：离开底部或最新页已回收时出现，到底后消失。与 Location Chatroom 新消息提示复用 `_LocationChatFloatingNotice`，底色0xCC1E1E24、圆角16、水平12/垂直8内边距，无额外边框或阴影，保留24px白色双下箭头；无新增自定义文案，辅助提示复用 Material 本地化末页标签。点击同步恢复当前 World 的首页缓存快照，再通过共享滚动协调器置底，不发 HTTP、不等待回载，也不自动刷新到服务端最新消息。恢复时只保留首页驻留正文、清除旧分页失败状态，后续仍用原游标读取更早页。折叠选择不重置。

- 标签激活、当前路由可见、PagePresentationScope、TickerMode 和应用前台共同控制请求。暂停取消请求、待调度加载和滚动防抖；恢复只续接被取消的操作。错误没有自动重试计时器，通过公共 Toast 和手动 Retry 处理。
- 首次进入 History 使用静态骨架并加载首屏。`WorldPage` 持有 `WorldHistoryViewCache`，保留分页窗口、正文投影、折叠选择及共享列表的有界布局缓存和稳定消息阅读锚点；切换标签或关闭再打开 Sheet 不刷新、不跳到最新消息，首帧恢复阅读位置。覆盖恢复／前台恢复同样不刷新已完成快照，仅续接被取消的必要操作。退出 World 释放缓存，无磁盘缓存；账号 sessionRevision（包括 Sheet 关闭期间）、服务实例／环境和 World 切换清空旧状态，晚到响应不能提交。
- History 消息列表首次挂载时继续显示静态骨架，真实列表在相同约束下透明布局；首次置底前提前测量含“在这里继续”卡片的末行，重开时先恢复阅读锚点。定位完成且相邻布局帧的视口、滚动位置及行边界一致后，同步显示消息和地点卡片；不使用固定延时，不等待图片下载。准备期间不写入临时阅读锚点，显示切换保留原列表实例。该流程仅由 History 启用，普通聊天室保持既有展示时序。
- 首次成功读取的首页另保留一份不可变消息列表快照，按当前 World/账号/环境隔离；切标签、关闭 History、后台切换和窗口回收均保留，退出 World 或身份/环境切换释放。显式刷新成功时随新快照替换。首页约一页额外正文不计入滚动窗口预算；正常逐页回到首页也复用此缓存。每页保留请求游标、响应游标、has_more、首尾消息 ID；滚动窗口正文驻留预算为 1,000 条唯一消息或 8 MiB UTF-8 正文字节。按远离阅读位置的外侧整页回收，保持连续驻留区；可见区、共享滚动器锚点、展开定位页及相邻页暂时固定，超大单页不截断。
- 访问已回收的较新或较旧区段时使用原请求游标（首页直接恢复缓存，不发请求）。两端分别判断已回收区段与服务器终点；稳定显示 ID 交给共享聊天滚动器恢复锚点。回载失败保留窗口，原游标可重试。回载内容变化优先保留原可见消息的位置；可见范围全部失效时定位到更新页靠近原阅读方向的可见行，折叠段使用标题。更新页无可展示内容时保留现有加载入口。游标链改变后的程序定位不触发续页，下一次用户拖动或显式加载才恢复分页。
- 元数据索引只依赖角色身份／头像和地点路径／图片字段。时间与 Tick 计数不重建索引；相关列表替换但展示值不变时保持版本。展示复用 LRU 默认 300，当前可见项可固定；额外弱引用复用共享 viewport 仍持有的 VM。折叠索引只持有显示 ID，分组不创建完整 VM。共享列表可遍历轻量 VM 以定位，但 History 的 Tick 正文与地点事件展示对象延迟到实际访问气泡内容时解析；类型判断与布局版本比较不触发解析，普通聊天维持原有构造及赋值行为。页移出、刷新或上下文切换清理派生引用。
- 地点连续段落只在数据／元数据投影变化后更新。折叠仅更新该段隐藏状态，记住用户操作的轻量 ID，使回载后保持选择。整页被版本过滤且还有下一页时显示手动加载入口，不自动遍历全历史。
- 普通 LocationChat 保持 `fcc6100b` 之前的列表排列与定位行为：直接使用回复投影，不接入跨地点历史排序；共享列表不会仅因 `active` 恢复就额外清空等待空间／阅读锚点或调用 `enter()`，实际进入／离开仍由页面原有生命周期处理。拖动开始时提前捕获锚点由 History 显式启用；吸顶标题布局仅在传入 History 标题构建器时使用。History 的折叠定位与阅读缓存继续保留。
