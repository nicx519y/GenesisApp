# 订阅报表指标方案

日期：2026-09-16。状态：报表设计；尚未接入后台或线上数据。

依据：`vip-purchase-analytics-draft.md`、当前 `subscription_analytics.dart`、`membership_purchase_tracking.dart`，以及现有 Worldo 报表的日志字段与读取逻辑。本方案使用现有 7 个订阅事件，不增加客户端打点。

## 1. 页面结构

在现有 Worldo 监控后台增加“订阅”页面，包含四块：订阅转化、入口效果、购买异常、游客绑定。顶部保留时间、环境、平台、版本筛选，新增入口、整页/Sheet、点击时登录状态筛选；按小时/天查看趋势。

第一版以页面访问和购买尝试作为转化单位。辅助展示去重设备数、已登录 UID 数，二者分别命名，不合并为“独立用户数”。

## 2. 订阅转化

| 指标 | 计算口径 | 用途 |
| --- | --- | --- |
| 曝光访问数 | `subscription_page_show` 按 pageId 去重；包括实际可见的加载状态 | 衡量订阅入口流量 |
| 点击访问数 | 已曝光访问中至少出现一次真实购买点击的 pageId 数 | 衡量有购买意向的访问 |
| 访问点击率 | 点击访问数 / 曝光访问数 | 衡量页面促成点击的能力 |
| 购买尝试数 | `subscription_purchase_click.object2` 去重；object3 为点击时选中的 yearly / monthly | 衡量真实购买尝试；同一访问可尝试多次 |
| 成功尝试数 | 有原始点击，且同一 object2 后续出现 `subscription_success` 的尝试数 | 衡量已确认完成的购买尝试 |
| 点击购买成功率 | 成功尝试数 / 购买尝试数 | 核心购买链路指标 |
| 成功访问数 | 已曝光访问中至少一次关联购买尝试成功的 pageId 数 | 与曝光保持相同统计单位 |
| 访问购买转化率 | 成功访问数 / 曝光访问数 | 衡量入口到购买的整体效果 |
| 成功交易记录数 | success 按平台 + 本笔订单号去重；缺订单号时按关联去重并单列缺号数 | 辅助观察交易确认量，不作为财务订单数 |
| 恢复成功记录数 | `recovery_` 关联的 success 去重数 | 单列恢复结果，不补造点击或计入点击转化率 |
| 未确认成功尝试数/率 | 原始点击尚未关联 success 的尝试数 / 购买尝试数 | 表示当前证据不足以确认成功，不等同于未扣款 |

分母为零时显示“—”。无原点击的普通 track_id 结果列为“缺失点击记录”，不得全部当成恢复订单。未关联曝光的点击仍可参与点击购买成功率，但不能参与访问点击率或访问购买转化率。

成功以 report.completed 对应的 success 为准。游客尚未登录或绑定不影响购买成功；claim.completed 不再增加购买成功数。先 failed/timeout 后 success 的同一次尝试仍计入成功，并保留过程异常。

未确认成功列表显示最后观测状态：pending、timeout、失败/取消/拦截、仅点击未见后续。这里的“最后”按客户端事件时间排序；同时间冲突显示多条证据，不猜最终状态。已成功优先于后续清理或重复传递的异常。

## 3. 入口效果

按 Home 会员入口、Me 会员卡、Me 粉钻、签到、聊天功能限制、Onboarding、Buy Gems 切入、未知来源分行。

每行展示：曝光访问数、点击访问数、访问点击率、购买尝试数、成功尝试数、点击购买成功率、访问购买转化率。支持按整页/Sheet、平台、版本继续筛选，保留样本数，不仅展示百分比。

所有订阅事件的入口来源均取 object1；购买、报告、登录或绑定不改变点击时保存的来源。找不到原始来源时为 from_unknown，不能用后来打开的页面倒推。恢复记录可以做“恢复来源分布”，但不能补进入口点击漏斗。

## 4. 购买异常

按实际证据分组：平台错误或取消、SDK 错误、客户端业务拦截、准备异常、report 错误/拒绝、准备超时、report 超时、平台 pending、report accepted。

每行展示：原始原因/错误码、事件次数、涉及尝试数、涉及设备数、涉及尝试占全部点击尝试比例、其中后续成功的尝试数、其中尚未确认成功的尝试数。恢复关联单独列示，不混入点击尝试分母。

- 同一尝试可能有多次 report 请求失败，也可能同时经历 pending、timeout、failed；事件次数与尝试数必须分开，各行尝试数不能相加作为总失败数。
- Google 展示主码和实际子码，Apple 展示实际 domain/code，SDK 展示真实 source/code；保留完整原始分类。只有明确且经过验证的码映射才能显示“用户取消”，不按 message 或模糊子串推断。
- `purchase_in_progress`、`downgrade_not_allowed` 等业务拦截独立展示，避免混成支付平台故障。
- 仅凭现有事件不能计算“report 请求失败率”：成功/pending 的去重粒度与失败请求粒度不同，缺少全部实际 report 请求数。
- “无后续事件”可能是用户仍在支付页、离开、进程退出或日志缺失，不能自动记作失败或超时。
- 点击明细可展开完整时间线：时间、action、原始 object3、事件当时 UID、原始关联 ID；便于核对重试后是否成功。

## 5. 游客绑定

游客购买按原始 subscription_purchase_click 的 UID 判断：有效 UID 非空为已登录，身份上下文正常时 UID 空为未登录。没有原始点击或无法确认上下文时列为未知；claim 的 UID 只反映请求发生时的身份。

| 指标 | 计算口径 |
| --- | --- |
| 未登录发起的购买尝试/成功尝试 | 取原点击 UID 状态，按 object2 关联 success |
| 已观测 claim 请求结果数 | `subscription_claim_result` 以 event_id 去重后的事件数 |
| claim 结果分布 | completed、accepted、rejected、error、timeout 分别统计事件次数 |
| claim 请求完成占比 | completed 结果次数 / 已观测 claim 请求结果数；不是用户绑定转化率 |
| 出现 claim 结果的关联数 | claim.object2 去重 |
| 已确认绑定关联数 | 至少出现一次 claim.completed 的 object2 数 |
| 尚未确认绑定关联数 | 出现过 claim 结果但未出现 completed 的 object2 数 |
| 绑定异常明细 | 实际 error 码、timeout、rejected、重复请求及后续 completed 时间线 |

一次 claim 可以覆盖同一游客身份的多笔购买，且当前事件没有覆盖订单列表；不得用 claim.completed 次数 / 游客成功订单数计算“游客订单绑定率”，也不能推断其他订单未绑定。当前没有登录曝光或登录结果事件，不制作登录漏斗/登录转化率。

## 6. 关联、时间与去重

1. 原始事件先按 event_id 去重；缺失 event_id 的异常记录单列，不能为了去重按 object2 + action 合并真实重试结果。
2. 页面访问用 pageId；购买尝试和对应 claim 用完整 object2。关联时不要要求 UID 一致，游客到登录会变化。环境必须隔离。
3. 访问指标按曝光日期归属，购买尝试指标按点击日期归属，再关联之后的结果；交易确认量与 claim 请求量按自身事件发生日期统计。页面明确标示每块时间口径。
4. 使用 app_timestamp 计算发生时间，created_at 仅用于入库延迟与数据更新时间。读日志时覆盖后续日期及晚到数据，不只在被选中的一天内做关联。
5. 首版结果标示“截至数据更新时间已确认”，最近数据会随回调和重试补齐。跨周期比较应使用相同观察时长，不能把尚未充分观察的新日期直接解释为转化下降。
6. 平台、版本、入口和登录状态筛选以访问/尝试开始时的上下文为准，先取完整关联再筛选，避免登录或升级后结果被筛掉。恢复记录使用可得上下文并标识原始状态未知。
7. 同一交易跨关联重复出现时，交易量只计一次；归因有冲突时进入数据质量明细，不任意给多个入口记功。客户端日志无法证明跨重装的绝对唯一，以服务端订单核对为准。

## 7. 可选辅助指标与数据质量

可增加成功样本“点击到首次成功确认”的 P50/P90 时长，名称固定为购买确认耗时。它包含用户在商店的操作、切后台和重试时间，不代表支付接口响应耗时。排除缺开始时间、负时长和明显时钟异常样本，并显示有效样本量。

数据质量小栏展示：未知来源、结果缺原始点击、点击缺曝光、成功缺订单号、无效关联、事件时间异常、缺 event_id、最近入库时间。平台按公共日志字段展示，联调时验证与真实设备一致，不从错误前缀猜所有事件的平台。

可按 subscription_purchase_click.object3 的 yearly / monthly 统计购买尝试的套餐占比，按 object2 关联 success 后统计成功尝试的套餐占比；缺原始点击的结果不能推断套餐。这反映点击时选中的套餐，不代表平台最终生效套餐或存量会员构成。

当前不做：收入/客单价、存量会员月付年付占比、首购/续费/升级、续费率/退订率、支付页拉起率、登录转化率、精确订单绑定率。现有事件缺少这些统计所需的字段或完整行为证据；需要业务订单或额外契约支持。

## 8. 后台接入检查点

现有 `worldo-api-dashboard/dashboard.go` 的 logEvent 已含 device_id、uid、event_id、app_timestamp、platform、app_version 及 object1–4。当前 `readLogWindow` 仅保留 API 与启动事件，订阅事件尚不能进入现有聚合，需增加订阅 action 白名单及独立聚合/API/页面。

上线验收需覆盖：重复日志去重；跨日成功；登录前后 UID 改变；同次点击失败后重试成功；多次真实 report/claim 结果保留；同一访问多次点击；隐藏 Tab 无曝光；恢复结果无点击；claim 一次覆盖多笔购买；缺号与归因冲突。当前文件只定义报表口径，不代表报表已上线或线上已有数据。
