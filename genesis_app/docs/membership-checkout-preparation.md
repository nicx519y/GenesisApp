# Apple / Google 订阅购买准备

Apple / Google 的订阅与 Gems 均使用内存商品缓存优先的购买流程。启动即预加载订阅（允许游客）；Gems 仅在已登录启动及登录成功后预加载。预加载包括服务端商品及商店商品对象，不调用游客 prepare，也不发起购买或 report。

进入支付页复用当前会话已完成的缓存及正在进行的查询，不再每次强制刷新。点击有有效缓存时不重新查询商品或价格；只有商店缓存缺失时查询商店，已有服务端商品信息不重拉服务端；两层均缺失才先请求服务端。失败／空的商店结果不算有效缓存，可再次补查。补查后展示价格、商品／优惠或权益变化，更新页面并结束本次点击，用户重新确认后才能购买。

Gems 完整页和购买 Sheet 在接受点击后立即展示原购买 loading，覆盖缓存确认、缺失数据补查和后续支付准备。订阅按钮在补齐目录期间立即进入 loading，保留金色底色；进入购买服务后由同一个购买弹窗覆盖 checking、preparing、store、reporting。早退、失败、需登录、价格变化及取消均结束本次 loading，不移除其他页面。

未登录用户点击购买时，读取当前会话商品响应中与 `last_account_uuid` 平级的 `has_subscription_order`；为 true 则先关闭检查 loading，再弹出已有登录弹窗并结束本次点击，不获取购买身份、不调用 prepare、商店购买或 report。如果此时离开页面，取消尚未调起商店的准备，迟到响应不能再发起购买。登录完成后由用户再次点击购买。已登录用户不受该登录条件限制，页面浏览及套餐切换不触发登录弹窗。该标志仅保存在当前会话的商品内存快照中，不写入展示磁盘缓存。

通过上述登录判断后，购买 UUID 两平台使用同一获取规则：优先使用当前商品接口的 `last_account_uuid`；为空时游客使用 `prepare` 返回的 UUID，已登录用户使用 `/user/info.uuid`。获取后直接传给商店购买，不与历史订单、商店回调或随后刷新的 UUID 比较。商店决定能否购买，回调凭据按原样 report，由服务端判定归属和权益；套餐变更只保留有效年会员转月会员的业务拦截。

回调关联与账号隔离：已通过 Apple checkoutAttemptId、已知交易 ID／purchaseToken 关联到本地订单的回调，不因商店返回 UUID 与下单 UUID 不一致而丢弃。Google 无 checkout 标记时，仍使用已调起商店且商品匹配的当前购买操作，并要求回调带非空账号标识；仅取消 UUID 相等校验，不放宽无 UUID 的未关联回调。订单保留本次下单 UUID，游客 report／claim 使用原身份，交易凭据保持原样；已登录订单继续校验 ownerUid。未关联的历史回调及恢复路径仍校验当前账号 UUID，不能只按同商品归属。仅 purchased 进入 report；pending、restored、取消与失败保持原流程，服务端 completed／rejected 决定结果。

- 订阅页拿到本次新鲜业务商品列表后，只预热当前选中套餐的商店商品。磁盘展示缓存不能用于准备。
- 预热时支付监听、本地订单读取、UID 与业务商品快照读取并行；然后只查询平台商品详情，不获取或创建购买 UUID。
- 真正点击购买后，才按 UUID 规则获取身份，并与商店商品查询或等待正在进行的预热并行；每次购买最多调用一次游客 prepare，已存在 last_account_uuid 时无需 prepare。
- 预热只获取商店商品，不拉起支付、不创建身份或付费订单、不授予游客自动绑定权限。真正点击后才获取购买身份并执行原订单保存及身份关联流程。
- 月套餐仍执行原会员降级检查；年套餐仍跳过该检查。准备不能绕过账号、商品和并发购买保护。

页面准备票据仍是单次消费、两分钟有效；票据重新准备时优先复用本次会话已查询的原生商品，不意味着再次向平台查询。底层商店结果按商店实例、商品类型、商品 ID 及优惠配置隔离，并合并同参数进行中的请求。原生 ProductDetails／offerToken 只存在内存，不能从磁盘展示价格构造购买凭据。

页面销毁、应用离开前台、套餐切换、商品刷新会丢弃页面票据并取消到期回调，但不清除会话商品缓存。重新进入支付页复用缓存；账号、业务商品快照或 catalogRevision 不匹配时不复用旧票据，消费前再次核对当前快照。账号切换、服务释放／环境替换清除原生查询缓存，迟到结果不写回新缓存。支付拉起被拒绝或抛错时使商店缓存失效，下一次只补商店查询；完成购买／claim 后，既有 catalogRevision 机制继续使订阅服务端资格失效并刷新。

Google 不保证已缓存 ProductDetails 长期有效；这里按产品要求跨页面复用当前会话缓存，不承诺平台凭据永久有效，也不自动重试付费操作。拉起失败后的重新查询仍需新的用户点击。不保证 Google 自身支付界面瞬间出现。

浏览页面、Monthly / Yearly 来回切换、两分钟商品预热刷新、回到前台，以及购买失败后恢复预热，均不调用 prepareGuest。只有点击购买且当前为游客、商品列表没有 last_account_uuid 时，才创建本次购买所需的临时身份。
