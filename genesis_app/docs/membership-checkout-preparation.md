# Apple / Google 订阅购买准备

Apple / Google 订阅共用页面级商店商品预热、点击购买时的身份选择及有效性校验；Gems 保持原流程。页面预热不会调用游客 prepare，也不会发起 report。

未登录用户点击购买时，先读取本次页面商品响应与 `last_account_uuid` 平级的 `has_subscription_order`；为 true 则直接弹出已有登录弹窗并结束本次点击，整个判断及登录过程不打开 Purchasing 弹窗，也不获取购买身份、不调用 prepare、商店购买或 report。为 false 时才显示 Purchasing 并开始购买准备。等待当前商品响应期间不展示购买弹窗；如果此时离开页面，取消尚未调起商店的准备，迟到响应不能再发起购买。登录完成后由用户再次点击购买。已登录用户不受该登录条件限制，页面浏览及套餐切换不触发登录弹窗。该标志仅保存在本次商品响应的内存快照中，不写入展示磁盘缓存。

通过上述登录判断后，购买 UUID 两平台使用同一获取规则：优先使用当前商品接口的 `last_account_uuid`；为空时游客使用 `prepare` 返回的 UUID，已登录用户使用 `/user/info.uuid`。获取后直接传给商店购买，不与历史订单、商店回调或随后刷新的 UUID 比较。商店决定能否购买，回调凭据按原样 report，由服务端判定归属和权益；套餐变更只保留有效年会员转月会员的业务拦截。

- 订阅页拿到本次新鲜业务商品列表后，只预热当前选中套餐的商店商品。磁盘展示缓存不能用于准备。
- 预热时支付监听、本地订单读取、UID 与业务商品快照读取并行；然后只查询平台商品详情，不获取或创建购买 UUID。
- 真正点击购买后，才按 UUID 规则获取身份，并与商店商品查询或等待正在进行的预热并行；每次购买最多调用一次游客 prepare，已存在 last_account_uuid 时无需 prepare。
- 预热只获取商店商品，不拉起支付、不创建身份或付费订单、不授予游客自动绑定权限。真正点击后才获取购买身份并执行原订单保存及身份关联流程。
- 月套餐仍执行原会员降级检查；年套餐仍跳过该检查。准备不能绕过账号、商品和并发购买保护。

准备对象只在当前页面内存中使用一次，从准备成功后开始计时，有效期为 2 分钟（客户端设定，并非平台承诺的有效期）。到期先丢弃旧结果；购买页面仍是当前路由、应用在前台且没有购买进行中时，静默重新查询平台商品，更新页面内存中的准备结果，成功后重新计时。刷新期间点击购买复用正在进行的查询；刷新失败不复用旧结果，点击时通过正常购买路径重新准备，不自动连续重试失败请求。

页面销毁、应用离开前台、套餐切换、商品刷新会丢弃准备并取消到期回调；被丢弃的查询即使随后成功，也不会重新启动计时。重新进入页重新查询。账号、业务商品快照或 catalogRevision 不匹配时不复用；消费前再次核对当前商品快照。不使用持久化 ProductDetails/offerToken。到期刷新只更新购买准备，不定时重拉业务商品列表或改变展示缓存。

Google 官方不建议缓存过时 ProductDetails，以免 launchBillingFlow 失败。本实现只将本次页面购买所需查询前移，不跨页面或跨购买复用。不保证 Google 自身支付界面瞬间出现。

浏览页面、Monthly / Yearly 来回切换、两分钟商品预热刷新、回到前台，以及购买失败后恢复预热，均不调用 prepareGuest。只有点击购买且当前为游客、商品列表没有 last_account_uuid 时，才创建本次购买所需的临时身份。

Debug 日志：

- `[Membership][prepare_timing] stage=query_store_product|load_account_uuid|prepare_guest elapsed_ms=...`
- `[Membership][checkout_timing] stage=launch_store elapsed_ms=... click_elapsed_ms=...`

不新增统计报表或生产埋点事件。计时不包含身份、凭证或响应内容。单元测试使用可控异步任务验证并行与复用；实际设备耗时仍需真机对比，launch_store 返回不等同于测量屏幕像素出现时刻。
