# LocationChat 轮次操作

本实现采用 2026-09-08 Go On 和轮次卡片协议。入口为
`LocationChatPanel`。Regenerate、Go On 不按会员资格隐藏，点击后由服务端判断 Gems 余额；Edit 点击及 Inspiration 展开时才检查会员与账号累计额度。
四个回复图标统一使用 `none` / `disabled` / `busy` / `idle` 状态：当前轮次不具备的功能从按钮布局移除；具备功能但其他回复操作正在执行时保留位置、图标置灰且不可点击；自身加载时显示转圈；可用时显示原图标。Regenerate 达到 10 张总卡（含原始卡）且生成结束后保留灰态按钮，点击只显示英文上限 Toast，不发起生成请求。四个按钮全为 `none` 时仍保留 32px 操作栏高度。
灵感回复接入 HTTP inspiration 接口，按来源轮次和卡片展示真实候选。

## 所有权与显示

`WorldChatroomService.replyActions` 持有当前登录 UID、世界下的
`ChatroomReplyActionsController`。控制器处理卡组、私有流、保存、
最终确认和 Go On 请求记录，页面只投影当前轮次与触发动作。

只对当前地点的最新 conversation 计算操作资格；表中 ✓ 仍须满足轮次已完成且有正式 AI 回复、连接就绪、未处于 Tick 锁或其他操作锁等条件。

| 最新 conversation | Regenerate | Go On | Edit | Inspiration |
| --- | ---: | ---: | ---: | ---: |
| `opening`，不限触发者 | — | ✓ | ✓ | ✓ |
| `user_enter_location`，不限触发者 | — | ✓ | ✓ | ✓ |
| `tick`，不限触发者 | — | ✓ | — | ✓ |
| 本人触发的 `user_message` 或 `go_on` | ✓ | ✓ | ✓ | ✓ |
| 他人触发的正常对话、未知或冲突元数据 | — | — | — | — |

候选卡获取、切换与 Regenerate 只用于本人正常对话；Enter、Tick、Opening 的 Inspiration 只使用正式轮次，不传候选 `card_id`。Regenerate 仍保留每轮 10 张回复卡（含原卡）上限。实时事件缺少 `conversation_type` 时等待正常历史同步，不从消息类型推断轮次类型。

候选消息标识包含世界、地点、轮次、卡片和全局消息 ID。
候选只替换对应轮次的 AI 回复显示，不写入正式消息缓存，不改变历史游标。
正式历史和候选中的 `character/narrator` 都是 AI 回复；`user_id` 表示轮次发起人，
不能据此渲染成自己的气泡。用户消息仍按用户身份和角色别名判断。
工具条是独立的轮次控件；切卡保持其视口位置，普通流更新遵守原底部跟随状态。
翻页只改变本地浏览位置，最终选卡由发送或外部新消息/Tick 触发。
重新生成和 Go On 点击时同步发起请求与 500ms 底部滚动，用户拖动可中断滚动。
等待首个 chunk 时显示圆角矩形气泡，底色和背景模糊层均复用左侧其他角色气泡配置（`otherBubbleColor`），
三个黑色圆点错峰循环缩放。start 帧不隐藏，首个 chunk 到达就移除；
切换卡片不再显示已隐藏的 loading，结束或失败也会移除，不写入消息缓存。消息下方不显示加载、待确认或错误文案，
错误沿用全局居中 toast：HTTP batch/cards/select 和 WS 操作失败均显示服务端 `err_msg`，
不替换为固定文案，不显示异常类型、错误码前缀或在编辑页重复插入错误文本。
重新生成流和生成结束事件的非零 `err_no` 同样进入全局失败通道；`10001` 保留登录失效流程。
同一 WS 错误经多条订阅或 Future/controller 转发时只提示一次；新的操作失败仍可再次提示。
灵感请求和发送共用此错误展示；请求不增加客户端自动重试。


## 保存与确认

编辑页必须接收完整、明确的轮次或卡片目标。只提交变更和删除：

| 目标 | 保存方式 |
| --- | --- |
| 无卡组或已经确认的正式回复 | 正式 batch；接口成功即完成本次编辑 |
| 尚未确认卡组内的原卡或候选 | 带 `card_id` 的候选 batch，以完整卡响应更新 |

编辑页的 Save 只以本次 batch 响应判断成功或失败，不发起、等待或校验正式历史刷新。
`conversation_range_updated` 按独立控制事件刷新正式历史，不回写本次 Save 的结果。
文字气泡修改为空白时转换成该消息的 `delete` 操作，不发送空白 `edit`。编辑页至少保留一个
气泡：删除按钮会拦截对最后一个气泡的删除，Save 也会合并显式删除和空白文字后再次校验；
任何全删 batch 都不会提交。
编辑页不订阅轮次冻结、自动确认或父聊天面板的解绑状态；所有本地异常、网络错误及服务端
`err_msg` 都通过全局居中 toast 展示，页面顶部不保留状态文案。
提交期间允许关闭页面；每次进入编辑页都从当时的消息快照创建独立会话，不恢复上一次页面草稿，
旧请求完成后也不关闭或修改后来打开的编辑页。

普通发送和 Go On 共用串行前置操作：持久化固定记录、保存草稿、确认卡片、
刷新正式范围。任一步失败即停止发送并保留草稿。
Go On 收到明确失败 ACK（包含 `2015`）后立即清除本次 pending，不把原回复轮次标记失效，
也不等待历史刷新；页面恢复失败前的回复操作按钮，错误继续只由全局 toast 展示。
候选编辑成功不自动选卡，翻页和页面关闭也不自动选卡。
外部新轮次或新 Tick 冻结当前完整卡；浏览未完成卡时固定此前浏览的完整卡。
删除批次结果不明时先查询，核对已经应用的操作和原目标，禁止盲目重发。

## 恢复

消息数据库 v5 的 `chatroom_reply_snapshots` 按
`owner_uid/world_id/location_id/round_id` 保存卡片正文、顺序、终态、确认与浏览位置，
以及带规则版本的操作支持依据。候选与正式消息分表，不占消息游标或条数。
HTTP 完整响应（包括明确空卡组）及候选流完成、编辑、选卡和翻页均更新快照。
浏览位置持久化为 `viewed_card_id`，页码由卡片顺序计算；重建服务后先恢复该卡片，
页面首帧直接显示对应正文和页码，不先渲染第一页再翻页。
生成中的正文不会覆盖上一份完整快照；按钮可点击状态根据当前连接、join、Tick 和操作锁实时计算。
卡片没有独立 TTL，断线保留正文；保留窗口跟随地点最近 200 条正式消息。
裁剪、删除、历史替换、缺口清理及清空缓存，在正式消息事务内清理无关联轮次快照。
独立 `genesis_chatroom_reply_actions.db` 继续保存草稿、基线和待恢复请求。
其中旧卡片按账号和地点幂等迁移；清空缓存的持久标记阻止再次导入。

WorldPage tilemap 入口先恢复本地完整首屏，再后台核验历史与卡片。
同一 WebSocket 会话内，join 复用已成功预加载的地点队列；预加载仍在排队或读取时
复用该任务，不额外刷新历史。仅有磁盘缓存、预加载失败、清空缓存或重连后仍补齐历史。
页面首帧同步采用已准备快照；历史先到时保留上一完整展示，卡片读取结束再整批发布。
冷启动显示真实空聊天页；失败保留完整缓存，没有完整缓存则显示取得的正式消息。
支持的操作在 join 前显示为禁用，会员与额度检查仍按原规则在点击时触发。
Origin Launch 和直接路由保持原展示流程。

ACK 后 30 秒未收到候选流，或候选流开始后 120 秒仍未形成完整终态（消息 end 或生成终态缺失）时，
客户端强制查询一次 `/cards` 恢复权威状态；查询仍为生成中则重新开始对应 watchdog，不自动重发 regenerate。
ACK 丢失时也只查询一次 `/cards`：已出现服务端候选则继续等待，否则移除本地占位并解锁。
watchdog 的恢复查询失败时将当前候选标为失败、显示对应网络/超时提示并恢复 Regenerate 操作。
确认选卡及写入结果不明的恢复查询强制读取服务端；失效前发出的旧响应不能写回缓存。
卡组读取属于 HTTP 历史加载流程：世界初始化预取、地点最新页、向上翻页、
区间刷新和地点快照都在历史合入后，读取这批历史包含的末尾自有完整轮次卡组，优先命中缓存。
后台地点预取不要求先 join；旧分页不包含末尾轮次时不重复查询该卡组。
历史任务完成包含卡组读取，卡组查询失败通过失败通道报告并保留已取得的正式历史。
卡组响应沿用历史请求代次隔离，旧结果不能覆盖新的历史或本地编辑、生成状态。
join 不再单独查询卡组，仅在统一历史加载后恢复待确认操作。
点击重新生成、打开编辑以及候选生成结束不额外查询卡组；若后续刷新正式历史，
则随该历史流程读取有效缓存或补拉。ACK 将本地原回复绑定到
原卡 ID，候选正文由私有流组装，终态事件补齐生成与计费状态。原卡包含同轮的
角色回复和旁白，不包含用户消息和事件。缺少完整正文时保留待恢复状态。
本地组装的原卡和候选保留各条消息的流式文本解码标记，确保生成结束及切卡后转义、换行显示一致；原始正文不改写，HTTP 卡片仍使用服务端正文的普通显示规则。
确认选卡、结果不明和重连恢复仍允许查询卡组。
查询和保存使用版本隔离，旧查询、迟到候选流不能覆盖新保存内容。

Go On 每次主动请求只发送一次。确认候选卡片等请求前置操作期间，点击时已有的按钮保留原有位置，Go On 转圈、其他按钮置灰，不因卡片确认而提前消失。请求成功并收到新轮次 ID 后，四个操作按钮同时进入 `none`，
在原操作栏位置显示与普通发送一致的三点 loading 气泡；新轮次首条非空回复开始渲染时移除。
Go On 不生成用户气泡。ACK 后 30 秒未收到新轮次流，或流开始后 120 秒仍未结束时，
查询该轮完整正式历史；已持久化 AI 回复即按成功恢复，否则显示超时提示、回到来源轮次并解除操作锁。
服务端明确返回 round error 时也立即结束 pending、回到来源轮次并解锁。
整轮 end 后即使正式历史为空也清除临时流，迟到分片不能复活该轮临时正文。
没有 ACK 时先刷新一次最新历史，再解除本地锁并保留原错误提示。当前协议没有按请求 ID
查询受理结果的接口，因此所有恢复路径都禁止自动重发；之后再次点击是用户明确发起的新请求。

## 候选卡切换动画

未确认卡组支持左右箭头和内容区域横向拖动。卡片内头像、气泡与旁白整体滑动，操作栏保持原位；内容高度在同一布局帧中插值，并通过滚动锚点补偿，适用于普通列表及带顶部历史提示的列表。箭头默认使用 240ms easeOutCubic，系统关闭动画时直接切换。

手势超过内容宽度 25% 或同方向速度达到 650 逻辑像素/秒后切换，否则回弹。首尾不循环，每次只翻一张；纵向滚动、长按与灵感列表横滑保留。动画只构建当前卡和目标卡，退出后释放旧卡。

预览通过 `messagesForCard` 只读本地卡片及流式内容，完成动画才调用现有浏览持久化；取消手势不写入。拖动及收尾期间由输入屏蔽层暂停翻卡、编辑、发送和回复操作，但按钮的 `none` / `disabled` / `busy` / `idle` 外观保持动画开始前的业务状态，不发生闪烁切换。新轮次、页面切换、选卡确认或操作状态失效会取消过渡；同卡流式更新和历史恢复不触发翻卡动画。

## 灵感回复

接口契约见 [inspiration-client-guide.md](inspiration-client-guide.md)。2026-09-09 提供的文档标注接口尚未发布，真实联调需先确认后端可用。

第四个按钮保留横向分页、侧卡点击居中和右侧编辑入口。候选条数由接口决定；不显示演示回复、剩余次数、购买提示或换一批入口。仅最新成功完成的轮次及已成功的当前卡片可请求，新轮次生成中不回退上一轮。灵感请求本身不依赖 WS ACK 或生成消息。

`WorldChatroomService.inspirations` 管理灵感缓存和请求。首次打开、重连后先以最新 HTTP 历史核验来源，再优先读取本地缓存；未命中才 POST `inspiration`，请求体只传 `conversation_round_id` 和可选 `card_id`，不传 `refresh`，仅该请求使用 120 秒超时。超时显示可重试提示，网络失败提示检查连接；失败、超时和取消都会结束 loading 并恢复按钮。沿用签名、鉴权及语言 Header，ID 保持 Dart int64。

独立数据库 `genesis_chatroom_inspirations.db` 按 `owner_uid/world_id/location_id/round_id/source_card_id` 保存完整候选及诊断信息。原始回复和 `is_original` 卡片均归于来源 0，其他候选归于真实 card_id。不同卡片缓存独立，编辑或删除正文不按内容哈希失效。新轮次、新正式消息推进会清除旧来源的全部卡片缓存；旧分页、重复推送与选卡范围回填不误清。切换页面或来源、断线和退出使在途结果失效，写入与清理串行执行。

读取无本地卡组的正式回复时，由响应解析实际 `source_card_id`，缓存仍写在实际来源键下，并记录该轮正式来源用于重启恢复。这也支持读取他人已采用候选的正式回复，无需访问其私有候选卡。客户端已知具体卡片时，响应必须匹配该卡来源。

点击当前灵感项固定文字及来源，复用 `finalizeBeforeSend(expectedSource: ...)`：保存草稿、确认同一来源卡、刷新正式范围后才发送普通用户消息。确认失败、来源变化或离开页面均不发送，不自动重发。已有生效卡无需再次选卡；无卡组则直接走普通发送。右侧编辑入口只填入输入框，用户发送时沿用普通前置确认流程。

## 验证边界

自动化覆盖接口契约、独立 SQLite 存储、控制器、页面按钮、异步编辑和滚动。
实际设备的触摸/键盘效果及后端生成、计费、退款和多端确认还需使用明确指定的
测试世界与地点联调，mock 测试不作为这些服务端行为的证明。
