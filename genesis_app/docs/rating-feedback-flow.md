# 手动评分、反馈和奖励流程

入口包括自动评分引导和 Developer → button → Rate Dialog；两种入口均仅允许已登录用户，游客静默跳过，不主动拉起登录。Debug 入口在登录后仍可重复测试。不实现 T+1。

## Debug 本地阈值

- Rate Dialog、消息阈值、本地配置应用／清除、Reset rating prompt 整组仅在确认登录后显示；游客及登录状态读取期间隐藏。监听会话及用户信息变更，登录后显示，退出后隐藏。

- Developer → button → Rate Dialog 下方的 Rating message threshold 支持输入非负整数。Apply 后本地值优先于 config.rating_prompt_message_count；0 关闭自动计数与引导。Use server 清除覆盖，恢复服务端配置。
- 本地值持久化，仅影响本机调试，不修改服务端 config，也不清空消息计数或自动已展示记录。本地未设置时保留原服务端行为；Debug 的 Rate Dialog 仍可重复手动打开。
- Reset rating prompt 仅清除当前用户身份的消息计数、消息去重、待弹出、自动已展示记录及本地奖励已领取标记（rating_reward_claimed_v1:<UID>）。点击后从零累计，重新发送达到阈值再退出相关页面可再次弹出。保留本地阈值、其他用户记录；不重置服务端发奖资格，重置后可重新展示领取入口，实际发奖仍以服务端幂等结果为准。

## 自动引导

- 仅已登录用户（复用 readLoginUid 判定）且最终生效阈值 > 0 时才记录 Location Chat 用户消息的发送成功回执；0 或负值关闭计数和自动展示。默认配置缺失为 0。
- 每个本机登录用户 UID 独立保存累计次数，跨地点、世界、会话和 App 重启累计。以 worldId + clientMsgId 去重，同一条消息的重试成功只算一次；发送失败、AI 回复和历史加载不计数。
- 累计次数达到阈值才持久化待弹出标记：阈值 20 时第 20 条成功消息达到条件。达到后不继续累积去重列表，等待离开页面。
- 在 Location Chat、World Detail（WorldPage）、Worldo Detail（OriginWorldPage）路由退出并完成退场后检查；若仍在这些页面中的任意一个，继续等待，关闭内嵌聊天／详情面板本身不触发。
- 只在前台、账号未变化、无其他弹层且 onboarding 不阻止弹窗时展示；有待领奖流程时先处理领奖，不重叠弹窗。
- 自动弹窗本机每用户一次，展示后即记已展示，取消也不再自动弹。重启不丢失累计／待弹出／已展示记录。待弹出记录不会在启动时直接弹，要等下一次相关页面退出。
- 自动入口复用已有星星、反馈、官方评分及领奖流程；Debug 入口不受自动一次限制。

## 弹窗后的流程

- 首次选星即锁定，禁止改选／重复点击。
- 1–3 星：保留已确认的 360ms 动画及反馈 UI，提交 feedback/create，始终带 rating；content 可选，非空时 trim 后提交，空白或未填写时省略该字段，仅提交星级。送出按钮初始可用，仅请求进行中禁用；失败保留输入，可重试。
- 4–5 星：提交仅 rating 的 feedback/create；失败保留评分，显示重试／取消，不开始奖励或官方评分流程。
- 提交前再次检查登录及会话版本，游客或会话已变化时不请求 feedback/create。
- 站内提交成功后关闭评分对话框并等待 route.completed，按登录 UID 持久化待领奖记录。不将站内评分冒充商店评分。
- 感谢弹窗允许领取 30 Gems（已发布接口契约），奖励不区分星级。若领奖弹窗打开后登录状态失效，领取时仍复用登录引导作为保护，登录后需再次点击领取；请求 task_code=rating，失败可重试。领取成功记录 UID 本地展示标记并刷新共享钱包。服务端按 UID 终身幂等是奖励去重的依据，本地标记不是发奖依据。
- 1–3 星提交站内反馈后进入领奖流程。若当前 UID 本地已记录领取奖励，则清理待领奖记录并直接结束，不再展示“已儲存您的回饋”等仅感谢弹窗；未领取时保留原感谢／领奖弹窗。4–5 星及恢复待领奖入口使用相同跳过规则，官方评分调用逻辑不变。
- 4–5 星每次只请求 Google／Apple 应用内评分，不打开任何应用商店或浏览器。Android 使用官方流程完成回调，之后显示领奖；iOS 请求正常返回后保留待领奖状态，待下一次 App 内主动触摸操作后展示，不使用固定延时。明确请求失败也不外跳，页面／账号仍有效时继续原领奖流程，不展示“无法打开商店”Toast。
- 待领奖记录跨重启保留；恢复启动后在当前身份下一次主动操作时显示，不重放官方评分。不同身份不读取彼此的待领奖记录；游客不展示历史待领奖弹窗。关闭／领取弹窗并等待退场完成后清除记录；发奖仍由服务端幂等控制。App 在后台、账号／页面已经变化时不立即弹出；官方请求失败仍保留已成功站内提交的领奖资格。
- 不再读取或写入旧版 rating_store_attempt_v1 标记，首次与后续请求均走应用内评分。
- Android 使用 requestReviewFlow / launchReviewFlow；iOS 使用 AppStore.requestReview(in:)（旧系统 SKStoreReviewController）。评分链路不保留 market://、itms-apps:// 或商店网页回退。
- 正常返回不说明系统框可见或用户已评价，不因“没有看到弹窗”自动跳转，不记录官方评价成功。
- 已领取的本地展示标记可能在卸载后丢失；奖励仍由服务端按 UID 去重。

官方接入在原生 device channel，Android 依赖 com.google.android.play:review:2.0.2；不引入新的 Flutter 评价插件。
