## 目录与依赖边界

- 当前目录与职责见 [README](README.md)。模块外调用统一从 `mini_phone.dart` 导入；World 持有 `session/` 会话，`mini_phone_page.dart` 负责外壳与路由。
- 正式功能在 `home/`、`messages/`、`posts/`、`photos/`、`music/`、`settings/` 使用独立 Widget；禁止重新以 `part` 共享手机外壳的私有 State。预览代码单独位于 `preview/`。
- Messages／Posts／Photos 控制器共用 `state/mini_phone_requests.dart` 的账号和请求版本，不反向依赖 Store 或页面；Store 负责跨功能协调和恢复，保持一个写请求日志和一套 World Socket。
- `shared/` 基础样式与控件不得导入页面、Session 或入口；有会话副作用的 Dock 放在 `entry/`。网络、SQLite 和通用动画继续遵循原目录职责。

## 必须保持的约束

- 地图页手机入口拖动期间左右两侧均使用底部面板高度 + 8 的边界，跨越屏幕中线不切换底部限制；抬手吸附右侧时才避让缩放按钮，沿用吸边动画。地点聊天保持自身底部间距。

- 入口样式只依据当前 World Detail 的 `info.map_style.era`，不从 Origin、标签或地图图片推断。现代/未来/末世使用 Classic，古代/魔法/维多利亚/蒸汽朋克使用 Grimoire；完整枚举映射见集成文档 Code entry points。World Detail 成功返回并应用前隐藏入口及其头像/音乐浮层；已应用的预取详情也算就绪。详情成功但风格缺失/null/未知时才回退 Classic。地图与地点聊天共享 World Scope 的就绪状态和风格；独立入口复用既有详情读取成功状态，不新增查询。

- 关闭操作只执行一次，并在延迟退出前确认目标 MiniPhone 路由仍为当前页；关闭与系统返回交错不得退出下层页面。账号读取及请求日志保存失败走公共 Toast，不产生未处理异步异常；身份初始化失败仍结束本地等待，重新进入或返回前台可重试。请求日志保存成功前不发送写请求，失败保留原请求键和草稿。
- 数据和写请求按环境、账号、世界隔离；上下文改变后丢弃旧请求结果，清除旧草稿和恢复页面引用。音乐播放进度例外：仅按环境、账号保存一条当前歌曲及进度，所有 World 共用；共享记录不存在时沿用首次读到的有效旧 World 记录，之后不再被旧记录覆盖，恢复保持暂停。正式 World 的播放器由 AppServices 常驻持有，退出 World 只暂停、保存进度并解绑世界埋点，下一个 World 复用歌曲目录、进度和已就绪解码器，不自动播放；每次进入 World（包括重新进入同一 World）清空入口 icon 的音乐显示状态，当前 World 播放／切歌后再显示音乐气泡和音符，暂停后保留入口控制；该显示状态与播放器历史、缓存及 Home 音乐卡片独立，异步恢复历史不得重新激活入口。加载中退出必须取消旧播放意图。账号切换、环境服务替换或应用服务释放时销毁旧播放器，独立预览仍随会话释放。
- 保存写请求 ID 与原始正文、图片和回复目标；同一次操作重试复用原请求，不建立自动重发队列。超时／断线保持待确认状态，不能据此判定 AI 最终失败。
- DM 提交时立即显示独立的本地临时气泡并清空原输入，不等待 HTTP、不在 Send 上转圈；正式消息仍只来自送达事件或历史查询，按请求键替换临时气泡、按完整 int64 消息 ID 去重和升序展示。明确拒绝撤回临时气泡并恢复草稿，不覆盖新输入；超时／断线保留待确认气泡和原请求键。空成功响应只表示操作受理／成功。新收到的多条回复首条立即显示，其余每隔一秒逐条显示，已有历史和历史分页不延迟；自动补查和去重不得提前显示排队消息。
- HTTP 200 下非零 `err_no` 仍为业务错误；展示原始 `ApiException.message`／`err_msg`，失败保留草稿。区分 Feed 的 `text` 和详情／提交的 `content`。
- 复用现有签名 HTTP client 与 World 的 V2 Socket，不创建手机独立连接、不为手机事件加入地点；手机事件不得进入 LocationChat 时间线或地点队列，不在页面硬编码环境地址。
- 事件按 `event_id` 去重，DM 消息再按完整 message_id 去重；Home 的 DM 列表与数量先建立本地基准，之后按唯一新消息和本地阅读更新，不按事件次数累加。合并刷新保留请求期间的新消息和阅读操作。Posts 通知、发帖及 Post 已读成功只刷新帖子通知聚合，不请求 Home／unread 或任何私聊接口；帖子独立调度，不等待私聊恢复，响应与 Home 按版本隔离，详见集成文档 Request scheduling。手机关闭继续处理世界事件，退出世界释放订阅；初始化、重连及返回前台只刷新 Home／未读聚合和已知会话的私聊恢复，不重拉应用列表。Home 使用世界时间，日期无法解析时留空；入口图标、Home 与设置预览共用会话世界时间；仅入口 icon 在时间缺失或无效时显示 `18:05`，Home 和设置预览仍留空。
- Messages 使用独立 SQLite 数据库，按环境／账号／World 隔离消息、会话、未读基准和待同步已读；首页 DM 聚合与角标只读本地投影。先恢复缓存再联网，Home 成功响应重建未读基准并保留请求期间变更；普通历史不自动成为未读。进入前台会话即本地已读，离线也生效，持久化后串行上报整会话已读；已读边界未推进且没有新未读时复用待同步记录，不重复上报；失败保留队列，重连／前台恢复／再次进入时重试，不回滚阅读。超过 Home 20 条明细的数量差额留待成功校准，不猜测归属。每会话保留最近 1000 条普通历史，未读、待确认和最后消息额外保留；退出世界不清库，存储失败显式 Toast。Posts 通知使用独立聚合查询。
- 聊天复用共享锚点列表、滚动协调器、`ChatMessageRow`、`ChatComposer` 和 `ChatKeyboardInsetLayout`，视觉采用 `kPrivateChatStyle`。发送保持键盘、不预留回复空白；阅读历史保留锚点和返回最新入口。
- “正在输入”是本地请求等待提示；仅 AI 会话等待期间允许编辑草稿、禁止再次发送，其他角色独立运行；按请求键查询历史中的 reply_status/failure，关联完整 AI 批次或服务端终态结束等待，终态不回退。peer_uid 非空的玩家互发不显示 AI 输入状态，气泡方向比较 sender_id 与当前 UID。
- 账号和本地缓存准备完成即启动手机列表，不等待 Home、角色资料或已读队列联网完成。同参数进行中的请求合并；筛选变化、写后确认及已读完成后的新校准不得复用过期请求。进入 MiniPhone 时并行预取 Messages／Posts／Photos 首屏到当前世界会话内存缓存；若直接进入其中一个页面，该页入口请求同时承担预取，避免重复。每次进入对应页面再刷新首屏；Posts 按下述独立筛选缓存校验已加载页。保留缓存直到成功应用，失败保留旧内容。Posts／Photos 仍允许用户下拉刷新，作者筛选与滚动分页保留；Messages 列表及私聊会话页不提供下拉刷新，保留进入页面同步、自动消息同步及历史分页；定时器、推送、重连、前台恢复、已读和写操作不顺带重拉这些列表（含作者列表）。未读聚合独立更新。发送成功及超时／断网等结果不明均启动只读恢复；仍未确认的首次私聊缺少会话 ID 时，按需跨页查询未筛选的 `/dm_sessions`，只绑定待恢复角色，不刷新应用列表。恢复使用原请求键，前台按 2→4→8→16→30 秒退避、整轮完成后再计时，同轮／同请求不得重叠；玩家发送取得本人正式消息后停止，AI 等服务端终态。进入后台暂停新增读请求并保留刷新和已读意图，前台恢复统一处理；已发出的网络操作可完成；后台完成的帖子写操作，其详情／评论确认延后至前台。
- Messages 仅用 `/dm_sessions` 返回的条目生成列表，不由 World／Home／消息缓存补齐；按 world_id + char_id 合并分页，已有条目结合缓存消息按最后一条消息的 delivered_at 倒序、同时间按完整 message_id 倒序排列，无消息条目保留服务端相对顺序并排在后面。聊天页中的送达／历史更新立即同步外层列表摘要和顺序，不等待重新进入 Messages 或额外请求会话列表；不使用世界时间 current_time 或会话 updated_at 排序。允许多个 dm_session_id=0 的虚拟条目；进入空聊天页，跳过消息和已读查询，仍按 char_id 发送，取得正数 ID 后替换对应条目。未读以服务端数量建立基准后由本地缓存更新；保留既有标题、列表及公共错误 Toast，不提供下拉刷新。
- Posts 默认展示已加载的全部世界角色头像（包括玩家角色），补充 `/post/authors` 返回的未知角色 ID；列表为空时仍保留角色，固定宽度槽位左对齐、可横滑；Create 位于最左侧，与后面的作者筛选组间隔 12；筛选组以圆形 `all` 按钮开头，内部显示小写文字，选中态沿用角色边框；点击清除筛选。筛选只传 `char_id`（玩家也用角色 ID），全部作者省略参数。All 与每个 char_id 在当前 World 会话内分别缓存帖子、已加载页和 hasMore；切换筛选立即恢复对应缓存及分页状态，冷筛选才为空，仍丢弃旧筛选的进行中响应。再次进入／切换筛选／下拉刷新从第 1 页校验至该筛选已缓存的末页（服务端无更多时提前停止），期间保留缓存，全部成功后按 post_id 和完整字段差异应用增删、排序及内容变化；中途失败不发布部分列表。未变化的帖子对象、列表引用及卡片控件复用，请求忙闲变化不重建 Feed；响应更新不重置当前滚动位置。缓存随 World 会话释放或账号／环境切换清空，不新增磁盘持久化。刷新 Feed 时保留筛选并刷新作者列表，相同作者 ID 列表复用缓存；通知不触发 Feed／作者请求。评论预览仅使用 Feed 的 `comments`，先取服务端倒序返回的最新三条，再按时间正序展示（返回第四条时显示无数量的查看全部）；列表不返回 `comment_count`，不推算总数，不逐帖请求评论或详情补齐；回复必须使用 `/comments` 的真实 ID。
- Posts Feed 使用按需构建的虚拟列表，只渲染视口附近；列表与 Post 详情共用缩略图组件：配图从加载前就固定占高 200，宽度使用正文区域全部可用宽度，不设额外最大宽度；图片按高度等比缩放，与正文区域左边缘对齐，超宽部分从右侧裁剪（BoxFit.fitHeight）。CDN 按高度和现有 DPR 上限缩放，预加载实际视口下方 5 条帖子的图片并与显示共用缓存。加载中／失败均留空，不显示占位图、错误图标或提示；点击时向通用大图浏览器传原图 URL 和当前缩略图 provider，立即复用缩略图缓存，待大图加载后替换；通过公共 `GenesisImageViewerSourceAnchor` 传入实际缩略图来源，实现通用打开放大动画，不在业务页复制动画；详情共用相同 CDN、解码、空白占位和大图预览策略。
- Post 详情由页面负责进入请求：先用 Feed 当条展示快照渲染原帖，无 Feed 时回退详情缓存；并行刷新详情和完整评论。每次进入评论区先显示 3 行静态骨架，不使用旧评论、Feed 预览或详情精简评论。`/comments` 每页取 100 条并自动取齐，按真实 ID 去重、published_at／comment_id 正序排序，全部成功后原子替换；取消评论滚动分页。当前页已有完整评论时刷新保留内容，失败不发布部分结果；首次失败结束骨架并走公共 Toast，可下拉重试。进入保持顶部，回复输入键盘弹起后等待完整数据及实际布局定位到底部；用户拖动取消跟随，发送成功全量刷新后重新定位，退出／切帖／切账号取消待定位。详细状态和验证见集成文档。
- 详情发送留言／回复时立即显示会话级本地留言、清空原输入并定位到底部；使用原请求 ID 去重，不伪造 comment_id，本地留言不可作为回复目标。明确拒绝撤回本地留言、空输入时恢复原稿及回复目标；结果不明保留本地留言，重试复用原请求及正文、回复目标。成功后从受理之后开始的完整评论查询原子替换本地留言，查询失败保留；关闭页面不取消发送，账号／World 会话释放清空。用户拖动仍取消跟随，较新的草稿不被迟到结果覆盖。
- 同帖点赞／取消点赞由 Posts 控制器统一处理乐观图标和数量增减，列表与详情共用显示状态；失败立即回滚至最近确认状态，连续点击保留最新意图并串行执行；成功后的详情查询失败不撤销已成功操作。结果不确定时查询详情，再处理最新操作意图；使用详情结果更新当前帖子展示，不重拉 Feed。进入 Posts 的全部已读只在本次进入成功加载后执行；从 Home 通知直达详情时，在该次详情成功加载且仍前台可见后同样执行当前世界全部通知已读，普通详情浏览不额外触发。两入口共用会话级已读流程，已触发后关闭手机仍完成上报与通知聚合刷新；失败保留提示并走公共 Toast，已读写请求不自动重放，聚合查询失败在重新打开手机、前台恢复或重连时补查。详情未成功加载或成功前已离开不触发，停留期间不自动清除新通知。
- 通知逐页替换，不按帖子合并、不制造通知 ID 或正文。Photos 保留虚拟三列网格，列表从原图生成 CDN 缩略图（原图为空才回退 thumbnail_url）；按格子宽度 × DPR（上限 2）在 90/180/360/720/1080 像素五档中取最近值，等距取较大档，宽高缩放 URL 均由公共 `buildGenesisCdnResizeUrl` 生成，统一 OSS resize/format 指令、替换旧处理并保留其他查询参数。保留共享查看器，传当前缩略图 provider 与公共来源锚点实现放大动画；多图打开及翻页预加载前后各一张大图，预加载 URL／解码尺寸／fit 与实际显示共用缓存，空原图不影响选中下标；发帖选图只做统一预处理和预览，不显示处理进度；本地预览按 108×144 与受限 DPR 解码，保持原比例及 cover 清晰度，上传字节不变；两端最长边 ≤4096、总像素 ≤1600 万、小图不放大，透明 PNG／不透明 JPEG 90%，超 10 MiB 继续等比缩小。点击 Post 才通过已有 upload/image 上传并发帖，按钮全程 loading；锁定正文和图片操作，返回／关闭仍可用，World 会话持有草稿及发送。失败保留草稿并复用已上传图片，保留完整 xl_url 及查询参数，允许纯文字。正文必填，新草稿限制 500 个用户可见字符并显示计数，仍保留后端 65535 UTF-8 字节检查；此前已提交但未确认的请求重试保留原正文，不截断；上传不超过 10 MiB。未确认写请求重试保留原图片 URL，不重新上传替换已提交内容。
